ISO 8583 – Bitmaps

El bitmap es el mapa que nos dice qué información contiene el mensaje. Viaja justo después del MTI y, antes de leer cualquier campo, el sistema lo mira para saber qué Data Elements vienen y cuáles no. ¿Cómo funciona? Es una secuencia de 64 bits. Cada posición corresponde a un Data Element: el bit 1 al DE1, el bit 2 al DE2… hasta el bit 64 al DE64. • Bit en 1 → el campo está presente. • Bit en 0 → el campo no viene en el mensaje. Leyendo el ejemplo En el gráfico, los bits en 1 están en las posiciones 2, 3, 7, 14, 21 y 40. Por lo tanto, el mensaje trae los DE2, DE3, DE7, DE14, DE21 y DE40. Por ejemplo: • DE2: número de tarjeta (PAN). • DE3: código de procesamiento. • DE7: fecha y hora de transmisión. • DE14: fecha de expiración. El resto de las posiciones están en 0: el sistema sabe que no debe buscar esos campos. Representación en hexadecimal En la trama el bitmap no se ve como 64 ceros y unos. Los bits se agrupan de a 8 (1 byte) y cada byte se escribe con 2 dígitos hexadecimales, así que el bitmap primario ocupa 8 bytes. En el ejemplo: Bits 1–8: 0110 0010 → 62 Bits 9–16: 0000 0100 → 04 Bits 17–24: 0000 1000 → 08 Bits 25–32: 0000 0000 → 00 Bits 33–40: 0000 0001 → 01 Bits 41–64: todo en 0 → 00 00 00 Bitmap: 62 04 08 00 01 00 00 00 El bit 1 es especial No representa un campo de datos: indica si existe un bitmap secundario. • Bit 1 = 0 → solo hay bitmap primario (DE1 a DE64). • Bit 1 = 1 → a continuación viene un segundo bitmap de 8 bytes para los DE65 a DE128. Así, la estructura del mensaje queda: MTI + bitmap primario + bitmap secundario (opcional) + Data Elements. Para llevarse: con solo leer el bitmap ya sabemos qué campos trae la trama y en qué orden vamos a encontrarlos.
