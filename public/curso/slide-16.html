Campos compuestos

Un campo compuesto es como una mini-transacción dentro del mensaje: en lugar de llevar un solo dato, contiene su propio bitmap interno que nos indica qué subcampos vienen empaquetados dentro de él.“ 📌 Puntos clave de la explicación 1. ¿Cómo se construye un campo compuesto? (Estructura) "Se compone de tres partes consecutivas: [Prefijo de longitud] + [Bitmap interno] + [Subcampos presentes]. El Prefijo nos dice cuántos bytes mide todo el bloque del campo compuesto. El Bitmap interno funciona exacto igual que el bitmap principal: cada bit en 1 indica la presencia de un subcampo (ej. 62.1, 62.2), y cada 0 indica ausencia. Finalmente, se colocan en fila solo los Subcampos activos en orden numérico ascendente." 2. Ejemplos reales en VisaNet (Sección Derecha) "Esta técnica se usa en los campos de datos privados de la red para enviar mucha información personalizada sin desperdiciar espacio:" DE62 (CPS): Datos del servicio de pago personalizado. Lleva un bitmap interno de 8 bytes (64 bits) para manejar subcampos del 62.1 al 62.26. DE63 (Additional Private Data): Con bitmap interno de 3 bytes (24 bits) para subcampos del 63.1 al 63.24. DE120, DE123, DE125 y DE127: Todos usan un bitmap interno de 2 bytes (16 bits) para gestionar hasta 16 subcampos adicionales (ej. datos de tokenización en el DE123). 3. Reglas de lectura y parseo "Espacio optimizado: Si un subcampo tiene bit en 0, sencillamente no se envía y no ocupa espacio. "Jerarquía: Para que un campo compuesto exista en la trama, primero su bit debe estar encendido en el Bitmap Primario del mensaje. "Formato: Cada subcampo dentro del contenedor tiene su propia longitud y codificación (BCD, EBCDIC o ASCII) definida por las especificaciones de VisaNet." 💡 Cierre / Remate para el público "En resumen: los campos compuestos le dan enorme flexibilidad al estándar ISO 8583. Nos permiten empaquetar decenas de datos específicos —como tokens o datos de lealtad— dentro de un único Data Element sin 'ensuciar' el mapa de bits principal de la transacción.
